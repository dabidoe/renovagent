## P0 — broken / embarrassing

### 1. `/landing.html` is an old, dead page still shipped under a different brand
`vite.config.js:9` still builds `landing.html` as an entry. It's DM Sans, says **"unpermitted."** in the preview frame, and the "inside the app" panel is an empty white box. Anyone who finds the URL sees a different product. → `13-stale-landing-html.jpg`
**Fix:** drop the entry (or redirect it to `/`). `legacy.html` is linked on purpose from error states (`workspace-app.tsx:1314`, `main.tsx:24`), so it can stay, but it should be `noindex`.

### 2. Brooklyn example shows **$0** everywhere
Header card: "Budget so far · 5 rooms **$0**"; every room tab shows `$0`. The room has no measurements, so nothing prices. As a showcase example it reads as broken. → `07-brooklyn-zero-budget.jpg`
**Fix:** either ship measurements in `public/examples/brooklyn/project.json` or show "Add sizes to price" in place of `$0` when no room is sized (`paint-floor-studio.tsx:1466`).

### 3. React duplicate-key error on every Brooklyn load
`paint-floor-studio.tsx:1771` (`<Imagine key={room.id}>`) and `:1780` (`<SizeEntry key={room.id}>`) are siblings with the same key. It fires whenever `SizeEntry` renders (any unsized room). React says this can duplicate or drop children.
**Fix:** use `key={`imagine-${room.id}`}` / `key={`size-${room.id}`}`.

### 4. "Save & prepare work plan" button has no horizontal padding
`.pf-inspo-go` (`paint-floor.css:1437`) has no `padding`; only certain parent contexts add it. In the Plan & budget tab (`room-plan.tsx:260`) the label runs into the pill edge. → `06-plan-tab-button-padding.jpg`
**Fix:** put `padding: 0 22px` on the base class.

## P3 — why this keeps happening

- **~20.5k lines of CSS in 20+ files** with only 33 custom properties total. Each feature file (`landing-v2.css` 1.2k, `landing-polish.css`, `workspace.css` 3.6k, `paint-floor.css` ~1.9k…) re-declares its own palette and type, and the "-v2"/"-polish" names suggest layers stacked rather than replaced.
- **`paint-floor-studio.tsx` is 1,983 lines.** Layout bugs (shared class reuse like `.pf-inspo-go`, duplicate keys) come from one component doing everything.
- **No visual or interaction regression checks.** A 10-route × 2-viewport Playwright screenshot diff would catch the *layout* defects here: padding, wrapping, overlaps, mascot boxes, chip-on-watermark. It would not catch:
  - **Budget semantics:** that an unsized room shows "add sizes" rather than `$0`.
  - **Accessible names:** whether a control has one.
  - **Disabled states:** whether a disabled control explains what it's waiting for.
  - **Persistence:** whether drafts and photos survive reload.
  - **Console errors:** for example duplicate keys.

  Those need explicit interaction assertions: role/name queries, state changes, reload checks and a console-error listener. They should sit alongside the screenshots.

## Suggested fix order

Fix the visible demo defects first, contained to the files they live in. Don't attempt a sweeping restyle while other work is landing. No time estimates here: several of these need a decision (copy, which example to show) as much as code.

1. **Visible demo defects (targeted, one file or a few lines each)** (done November 3; see PROGRESS.md):
   - Remove the `landing.html` entry.
   - Fix the Brooklyn `$0`: ship sizes, or say "add sizes to price".
   - Fix the duplicate keys.
   - Add base padding to `.pf-inspo-go`.
   - Keep the "Before" chip off the MLS watermark.
   - Fix the eyebrow gap.
   - Give the mascot a transparent background.
   - Swap the "Keep the stairs clear" placeholder.
   - Use readable model names in copy.
2. **Hero and landing edit** (done November 3, except the hero photo choice and logo knockout, which are owner decisions): pick one room story, reduce the CTAs, fix the overlay path and hotspot placement, replace or label the pricing bars.
3. **Studio layout** (done November 3, except Design-tab copy, which main reorganized, and desktop dead space; see PROGRESS.md): one budget surface, de-duplicate the Design-tab copy, mobile header/actions/tabs, visible intake labels, explained disabled states.
4. **Guardrails:** commit the screenshot script *and* interaction assertions (budget text for unsized rooms, accessible names, disabled-state explanations, reload persistence, zero console errors) for the demo routes.
5. **Consolidation, later and incremental:** the P2 token/button sprawl is real, but a rewrite across every CSS file now would add regression risk to working demo surfaces for little visible gain. When it happens, do it one surface at a time behind the guardrails from item 4. A sensible first step is collapsing the in-file `--pf-accent` redefinitions in `paint-floor.css`, which fixes the two-blues-on-one-page issue without touching other files.
