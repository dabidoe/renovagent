# UI audit — November 3, 2026

Scope: every public route at 1440 px and 390 px, plus a few interactions (mobile menu, studio tabs, keyboard focus). Local `npm run dev` (Vite only, no API), headless Chromium. The crops referenced below are in [`ui-2026-11-03/`](ui-2026-11-03/).

Routes covered: `/`, `#examples`, `#example/oakland`, `#example/brooklyn`, `#example/bedroom-refresh`, `#example-house`, `#your-project`, `#connect`, `#compare-tools`, `/landing.html`, `/legacy.html`.

**Caveats.** The sandbox blocked `api.fontshare.com`, so Satoshi fell back to Inter in these screenshots. Headline weight and letterspacing may look slightly different in production. `/api/*` returned 500 because no API was running, so signed-in and saved states were not audited. The 3D viewer was not exercised.

Severity:
- **P0**: broken, wrong, or embarrassing in public.
- **P1**: visible jank a user will notice.
- **P2**: ugly or inconsistent.
- **P3**: systemic debt that keeps producing P1/P2s.

## P0 — broken / embarrassing

### 1. `/landing.html` is an old, dead page still shipped under a different brand
`vite.config.js:9` still builds `landing.html` as an entry. It's DM Sans, says **"unpermitted."** in the preview frame, and the "inside the app" panel is an empty white box. Anyone who finds the URL sees a different product. → `13-stale-landing-html.jpg`
**Fix:** drop the entry (or redirect it to `/`). `legacy.html` is linked on purpose from error states (`workspace-app.tsx:1314`, `main.tsx:24`), so it can stay, but it should be `noindex`.

### 2. Brooklyn example shows **$0** everywhere
Header card: "Budget so far · 5 rooms **$0**"; every room tab shows `$0`. The room has no measurements, so nothing prices. As a showcase example it reads as broken. → `07-brooklyn-zero-budget.jpg`
**Fix:** either ship measurements in `public/examples/brooklyn/project.json` or show "Add sizes to price" in place of `$0` when no room is sized (`paint-floor-studio.tsx:1466`).

### 3. React duplicate-key error on every Brooklyn load
`paint-floor-studio.tsx:1771` (`<Imagine key={room.id}>`) and `:1780` (`<SizeEntry key={room.id}>`) are siblings with the same key. It fires whenever `SizeEntry` renders (any unsized room). React says this can duplicate or drop children.
**Fix:** use `key={`imagine-${room.id}`}` / `key={`size-${room.id}`}`.

### 4. "Save & prepare work plan" button has no horizontal padding
`.pf-inspo-go` (`paint-floor.css:1437`) has no `padding`; only certain parent contexts add it. In the Plan & budget tab (`room-plan.tsx:260`) the label runs into the pill edge. → `06-plan-tab-button-padding.jpg`
**Fix:** put `padding: 0 22px` on the base class.

### 5. Internal model IDs in user-facing copy
Bedroom refresh: "Generated by **muse-image-1.0**…", "**muse-spark-1.3** named them, **sam-3.1** outlined each one" (`inspo-example.tsx:45`). Fine as an engineering receipt, but jargon for a homeowner. Also "What Muse changed" uses strikethrough for the before-state, which reads like a diff. → `12-bedroom-copy.jpg`

## P1 — jank

### Landing hero (`01-hero-desktop.jpg`, `02-hero-mobile.jpg`)
- **Topic mismatch.** The hero photo is a bathroom (vanity, shower tile), the prompt placeholder says "living room", and every section below is living rooms. Pick one story.
- **The SAM outline overlay runs through the headline.** The light-blue outline path crosses "Turn your space" and the prompt box on desktop. On mobile it's a stray vertical line on the right edge with no visible subject.
- **The "Shower tile" hotspot floats in empty space** next to the headline, not on any tile.
- **Mobile: the product card covers the vanity**, the very thing it describes. Above the fold you get headline, prompt, 3 stacked pill CTAs and a card, about 6 competing actions.
- **CTA soup.** "Start a project", "Try your room in the studio", "See listing examples", "Connect with Muse or your agent", "Open workspace", "Studio", "Connect your agent": seven entry points on one screen. Two pairs say the same thing in different words.
- **Card tab "Shower tile" wraps to two lines** on desktop, so the tab row has uneven heights.
- **Logo sits in a white rounded chip** over the photo. It looks pasted on. Use a white/knockout logo variant on dark imagery.

### "Plan with Muse." section (`04-muse-mascot-box.jpg`)
- The mascot is a rectangle with its own off-white background, placed between the copy column and the card. It doesn't line up with either and its box edge is visible. Same on Connect (`09-connect-mascot.jpg`). Use a transparent asset or put it inside a framed card.
- Large dead space above "Plan with": the heading is vertically centered against a taller card, so the left column floats.

### Pricing comparison (`03-pricing-bars.jpg`, `03b-…`)

### Studio (Oakland/Brooklyn/Philadelphia, `05-studio-header.jpg`)

- **Dead space under the image** on desktop: "Download preview" plus ~200 px of nothing, then an orphan "▸ Sources".

## P3 — why this keeps happening

- **~20.5k lines of CSS in 20+ files** with only 33 custom properties total. Each feature file (`landing-v2.css` 1.2k, `landing-polish.css`, `workspace.css` 3.6k, `paint-floor.css` ~1.9k…) re-declares its own palette and type, and the "-v2"/"-polish" names suggest layers stacked rather than replaced.
- **`paint-floor-studio.tsx` is 1,983 lines.** Layout bugs (shared class reuse like `.pf-inspo-go`, duplicate keys) come from one component doing everything.
- **No visual regression check.** Every bug above would be caught by a 10-route × 2-viewport Playwright screenshot diff. The script used for this audit is ~40 lines and could live in `scripts/`.

## Suggested fix order

1. **Quick wins (≈1–2 h, low conflict risk):** P0 #1, #3, #4. Add padding to base buttons, fix the Brooklyn `$0` display, fix the eyebrow gap, label the intake inputs, remove model IDs from copy, give the mascot a transparent background.
2. **Tokens pass (½–1 day):** one `tokens.css` with a single accent, a type scale (12/13/14/16/18/22/28/36/48/76), a radius scale (6/10/16/pill), and one button component. Replace `--pf-accent`, `--landing-blue`, `--ca-accent`, `--blue` and `--brand-blue` with it. This removes most of the "ugly" in one pass.
3. **Hero and landing edit:** pick one room story, cut CTAs to two (Start a project / See examples), fix the overlay path and hotspot placement, replace the pricing bars.
4. **Studio layout:** one budget surface, de-duplicate the Design-tab copy, mobile header/actions/tabs, shared page container across gallery/studio/connect/intake.
5. **Guardrail:** commit the screenshot script and run it in CI.

Since other work is in flight, items 1 and 5 touch the fewest shared files. Item 2 touches every CSS file, so it's best done when the studio branch work has landed.
