## Selective reuse for the first release

Use the existing **OpenPlan3D-compatible import** as the commercially permissible open-source path. Upstream is MIT and describes a SvelteKit/Three.js editor. Renovagent already follows its file/coordinate conventions. Continue accepting its JSON through the shared parser; the native client does not need its editor, capture app, browser stack, or demo plans. Track applicable MIT notices if shipped parser logic contains derived portions, and verify the exact upstream/source history before release. **Low** incremental dependency cost, **medium** validation effort for native parity. [OpenPlan3D](https://github.com/laanlabs/openPlan3D) · [Existing parser](../../packages/core/src/geometry/room-model.ts) · [Existing compatibility tests](../../tests/domain/floor-plan.test.ts)

Use Apple system frameworks plus the existing narrow Zod-backed bridge. Zod is MIT. If generic 3D assets become necessary, the existing Kenney CC0 set is a candidate, subject to verifying the particular asset and its manifest. The MVP uses schematic shapes. Owner-supplied bathroom meshes and demo photos require separate distribution rights. [Zod license](https://github.com/colinhacks/zod/blob/main/LICENSE) · [Kenney inventory](../../public/furniture/kenney/README.md) · [Bathroom asset restrictions](../architecture/bathroom-assets.md)

Before approving any new third-party source, record the pinned revision, files and modifications, exact license/notice text, dependencies actually shipped, service/weight/data/asset terms, and a named maintainer. Require a fixture-based comparison showing the candidate beats a smaller native implementation. Treat unresolved rights as a release blocker for that component. Use independently captured consented fixtures and synthetic media for evaluations.
