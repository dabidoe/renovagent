# iOS architecture and project model

**Phase 0 proposal · November 10, 2026**

Build a native SwiftUI, local-first planner. Swift owns capture, presentation, and file storage. The existing TypeScript domain remains the source of rules. The launch workflow uses no account, Renovagent network request, cloud sync, model inference, or checkout execution. The existing website/API/MCP keep their own working entry points. [Repository audit](EXISTING_CAPABILITIES.md)

## Execution path and decision gate

| Path | Assessment |
| --- | --- |
| **SwiftUI + bundled JavaScriptCore bridge** | Recommended if the first device proof passes. Reuses TypeScript contracts and deterministic rules offline without a web view or Node runtime. Bundle a narrow build-time entry with the existing build tooling and Zod. Test the resolved module graph, SDK built-ins, speed and rights before committing to it. **Medium–high**. [JSContext](https://developer.apple.com/documentation/javascriptcore/jscontext) |
| **SwiftUI + current HTTP domain** | Sensible for later connected workflows. Existing JSON commands and server validation are a head start. A native session, owner-scoped project read model, offline retry/conflict design, and an explicitly funded service are still needed. HTTP-only planning would change the proposed free/offline promise. **High**. [Server](../../apps/api/src/server.ts) · [HTTP repository](../../apps/web/src/adapters/http/project-repository.ts) |
| **Swift rewrite or WKWebView shell** | Swift rewrite duplicates calculation and release semantics. A shell reuses pages but leaves a browser workspace, bridge/auth complexity, and separate capture UI. Neither is the shortest path to the requested native, offline workflow. **High** rewrite or **medium** shell with reduced fit. |

Expose a small JSON-in/JSON-out bridge for workspace load/validation, command batches, normalized geometry, scope/quantity projection and reviewed purchase preparation. Call function values with data arguments, never interpolate input as code. Load only immutable JS shipped in the signed app, with no network or native privileged API exposed to JS. Serial execution off the UI thread, strict input size/depth caps, structured errors, and atomic persistence guard the boundary. `handleCommand` uses `structuredClone` and modern JS methods. Prove their availability on the minimum OS or supply a narrowly tested clone for the JSON-only bridge, plus build-target transforms as necessary. Do not ship the browser `Blob` repository port as a runtime dependency. Inspect transitive core imports for code text, model configuration or assets before bundling. If the bridge cannot meet parity, bundle size, runtime or distribution gates, pause for an owner decision between a connected first release and a smaller offline scope. [Command handler](../../packages/core/src/domain/handle-command.ts) · [Workspace contract](../../packages/contracts/src/project.ts) · [Core entry](../../packages/core/src/index.ts) · [App Review guidelines](https://developer.apple.com/app-store/review/guidelines/)

Keep the app's authoritative local records in its private Application Support container. A single Swift repository actor applies a validated command batch to a temporary state, stages bounded immutable files by digest, then atomically swaps the manifest that references those files and records command results. Recover or garbage-collect unreferenced files after interruption. Keep one recoverable previous manifest and read-only recovery for newer/unsupported schemas. Use file protection, bounded caches and explicit deletion. Expose a local backup/export policy before shipping, including whether originals enter OS-managed backup. Do not silently import web projects, claim cloud backup, or merge two authoritative histories. Restrict the App Group to a small pending-link inbox. **Medium** native storage work. [Existing transaction semantics](../../apps/web/src/adapters/indexeddb/project-repository.ts) · [Migration baseline](../../apps/web/src/adapters/indexeddb/migrations.ts) · [App Groups](https://developer.apple.com/documentation/xcode/configuring-app-groups)

## Typed records and revision chain

This is an additive model proposal. Reuse the existing workspace envelope, facts, artifact lifecycle, input references and command handling. Names below describe proposed artifact kinds. No schema change has been made.

| Record | Identity and dependencies | Proposed role |
| --- | --- | --- |
| **Property → Space → Project** | Existing IDs, owner, project revision, scope and referenced spaces. Project selects a playbook and version. | Multiple rooms and project types remain possible. Bathroom is a playbook. Current dimension facts are project-scoped. Keep that behavior for compatibility and reference the exact facts rather than silently promoting them to shared property data. |
| **Evidence and facts** | Evidence ID, attachment digest and media type, capture method/time, provenance, visibility, original unit. Fact versions carry assertion and a separate verification record when established. | Capture observations, tape corrections, merchant or manufacturer sources, and attributed contractor replies. Preserve contradictory inputs for resolution. A derived display value does not overwrite a source fact. |
| **Observed room revision** | `spaceId`, baseline artifact revision, capture evidence ID, input fact refs, normalized geometry and element IDs, origin/axes/units and observation basis. | Keep source element keys under capture ID. Allocate stable app IDs within the baseline. A rescan creates a new baseline. Carry an edit forward only through explicit reviewed mapping. Unknown walls/connection points remain unknown. |
| **Scope change and work** | `changeId`, baseline ref, affected element(s), keep/replace action, desired state, playbook version. Draft work/quantities cite the change and facts. | Native editing changes intent. Shared code derives affected work and quantities. Proposed product placement is a separate schematic layer. |
| **Product selection** | `selectionId`, exact change/requirement ref, user-saved link, manufacturer model/variant and merchant SKU where confirmed, evidenced spec assertions, quantity, supply status and optional quote observation. | Keep private links out of the shared catalog. Supply status is homeowner, contractor, allowance or TBD. Unknown hard constraints produce needs input or review. |
| **Review and issued packet** | Decision/response binds baseline, change, selection, relevant facts, review packet digest/revision, author attribution, review date and limits. | Contractor feedback returned externally is recorded by the owner as attributed evidence. Keep the contractor's identity unverified in the local flow. A response to an old packet remains history. |
| **Purchase preparation** | Versioned lines bind exact selection, review, approved scope and quantity revisions. Include buyer, merchant link, pack/unit and price basis when known, with explicit exclusions. | Separate research link, review pending, current prepared line and stale line. A saved link alone never produces an approved line. No order or payment record is created. |

Use the [domain specification](../architecture/03-domain-and-contracts.md), [workspace records](../../packages/contracts/src/project.ts), [facts and evidence](../../packages/contracts/src/facts.ts), [artifact envelope](../../packages/contracts/src/artifacts.ts), [dependency invalidation](../../packages/core/src/domain/invalidate.ts), [scope](../../packages/contracts/src/scope-draft.ts) and [commerce contracts](../../packages/contracts/src/catalog.ts) as the baseline. Add narrow validated operations for recording a baseline, editing scope/selection, recording a response, and preparing a list. Agents may propose against refs. The shared domain rejects stale, foreign, or out-of-scope input. A new vanity SKU stales its previous review and list line. A corrected width stales checks using that measurement and can block the list, while unrelated facts and historical packets remain available. Offer expiry is a separate explicit check because shared catalog updates do not drive workspace invalidation today.

## Boundary for later connected collaboration

Export a redacted PDF and purchase CSV locally through the system share sheet. Preview exactly what is shared. Exported files can be forwarded, so describe this clearly in the UI. Keep raw scans, addresses, private trade pricing and full-resolution media out by default. Contractor answers can return via the same communication channel and be recorded against the cited packet. A true invite/reply identity, revocable sharing, media TTL and optional sync require authorization, token and deletion semantics before reusing hosted infrastructure. Existing bearer-link studio sharing does not establish those permissions. [Current share behavior](../architecture/limited-guest-sharing.md)
