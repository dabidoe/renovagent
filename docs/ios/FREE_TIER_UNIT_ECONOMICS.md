# Free-tier unit economics

**Phase 0 · November 10, 2026 · USD**

A free user should be able to measure a bathroom, save photos and links, compare a replacement, collect contractor feedback, and export a reviewed purchase list with **zero Renovagent-hosted requests in the core flow**. This is an architectural target. No native request traces, hosting invoices, cloud quotas, model prices or usage mix were measured for this audit. Support, signing, device testing, release maintenance and privacy operations still cost money.

## Example budget and sensitivities

Public price references at review time are Apple Developer Program **$99/year**, Railway **$0.05/GB egress** with plan and usage-based compute, and Modal **$0.000164/T4-second** before other resources and credits. Actual Railway/Atlas plan, storage, database transfer, and regional or negotiated provider rates remain unknown. Do not treat any of these examples as an account invoice. [Apple enrollment](https://developer.apple.com/programs/enroll/) · [Railway rates](https://docs.railway.com/pricing/plans) · [Atlas pricing](https://www.mongodb.com/pricing) · [Modal rates](https://modal.com/pricing)

| Illustrative case | Inputs and result | Meaning |
| --- | --- | --- |
| Local-only launch | 10,000 active users × 0 hosted actions = **$0 in variable Renovagent cloud usage attributable to the core flow**. Annual Apple fee alone is about $8.25/month averaged over the year. | Existing web hosting, devices, support and engineering are separate and still incur cost. Distribution, buyer link openings and any user-controlled OS backup are not Renovagent API usage. |
| Future hosted packet | Assume 500 publishing users/month, one 6 MB packet each, three full downloads per packet. **3 GB new storage/month**, **9 GB egress/month**, about **$0.45 Railway egress** if all downloads traverse Railway at the listed rate. | Excludes DB/object storage, backup, auth, CPU and retries. At one-year retention with no deletion this cohort pattern holds about 36 GB before copies, versus roughly one 3 GB cohort at 30 days. Public view amplification can dominate. |
| One cloud render per active user | Assume 10,000 renders × 120 billed T4 seconds × $0.000164 = **$196.80 GPU-only/month**. At 540 billed seconds the same volume is **$885.60 GPU-only/month**. | Hypothetical durations, not measured. CPU, memory, cold starts, outputs, retries and support are extra. |
| One model workflow per active user | At an assumed **$0.10** all-in variable provider cost/job, 10,000 jobs add **$1,000/month** before fixed/support costs. At **$0.50**, **$5,000/month**. | Sensitivity assumptions, not vendor prices. Measure per operation and count failed/duplicate calls too. |
| Video originals | Assume 10,000 uploads × 30 MB = **300 GB new originals/month**, before frames, multiple downloads, generated geometry, backups or inference. | Measured input size and retention decide the actual bill. Raw video is outside the MVP. |

For a connected pilot track `fixed incremental infra + API/DB usage + retained GB-month × storage rate + transferred GB × egress rate + metered calls/GPU time + support`. Separate incremental iOS spend from shared web allocation. Divide by active iOS users and by completed outputs to capture both monthly economics and waste. Include peak abuse/retry cases. Budget controls must count actual operations, not just user clicks.

## Gates to approve before any cloud allowance

- **Launch defaults:** propose at most ten retained photo evidence files per project, a 6 MB redacted export cap, and bounded scan input, with a clear local storage meter and user deletion. Test actual sizes on supported devices. Show the user when an export must be reduced. Keep private originals out of exports and set a backup policy before distribution.
- **Offline proof:** run the full bathroom scenario in airplane mode and with networking enabled under instrumentation. Pass with no Renovagent HTTP, model, merchant preview, share-hosting or telemetry requests before an explicit user-driven external action. SDK analytics and crash tools require separate review.
- **If connected work is later approved:** begin with a bounded test cohort. Propose one explicit opt-in packet per project, selected derivative bytes only, 30-day expiry, and hard per-owner and global byte/request ceilings. Give operators a kill switch for expensive work and retain support/audit events without private content. Track cost, bytes, retry ratio, p50/p95 job runtime, completion and deletion.
- **Business gate:** agree on an all-in monthly ceiling and measurable benefit before any free hosted allowance. Keep local planning functional when quotas or services fail. Get separate approval for support time, developer membership, test devices and any later supplier/model/hosting spend.
