  
1. Furniture is a label, not a capability. Imagine text asking for a sofa, coffee table, or rug left the image and total unchanged. The only change was the “Not priced” line — and each new request *overwrote* the previous label, instead of accumulating. So “rug · coffee table” replaced “white floor,” it didn’t add to it. If you’re building scope from that label, you’ll lose items silently.  
2. Search links are presented like products. Inspiration items (white sofa, lounge chair, pendant) each got Amazon / Wayfair / Target search links, not a picked product with dimensions, price, or retailer. A user can easily read that as “Renovagent found this sofa” when it didn’t — it found a search.  
3. The rug is the exception that proves the rule. The striped rug *did* appear in the Inspired photo edit, but it’s not in the shopping list at all, and not even in the “Not priced” line. So the one furniture/accessory item that actually rendered is the one with no quantity, no price, and no line item to act on.  
4. No fit check anywhere. No check for whether a sofa, chair, rug, or pendant fits a ~14′ × 20′, 8′ room, or for electrical/clearance. That’s not a nice-to-have for furniture — without dimensions, a render is just a picture.  
5. Image / scope / total don’t move together. Black walls changed the live image but not the static Inspired image; Budget changed the total but not the image; a rug request changed a label but neither. For furniture, that means you can’t trust any one view to tell you what the design actually is.  
“You know, THIS feature would be nice” — from those breaks  
* A real furniture picker: pick an exact product (with dimensions, price, retailer, and a link to *that* product, not a search), place it in the render, and have it appear in scope and total together — or explicitly say “unpriced, for visual only” in the same place, every time.  
* Add / remove / keep furniture as first-class controls: “keep existing sofa” should work even when the sofa isn’t visible — ask what sofa, or say “no sofa detected, add one?” — instead of silently ignoring it. Same for “replace the coffee table” when there is no coffee table in the photo.  
* Fit check as a default step: before a sofa/chair/rug is added, show its footprint against the room’s (user-confirmed) dimensions, with clearance warnings. That’s the difference between a render and a plan a contractor can build from.  
* A furniture scope that accumulates: rug + coffee table + sofa should be 3 line items, not one label that overwrites the last one. Removal, delivery, assembly, and electrical for pendants should be in that scope, not just paint/floor materials.  
* A render you can reopen: right now there’s no image URL, save, or share link for any render. For furniture especially, a user needs to send *that* image to a partner/contractor — “open the project page and find the slider” isn’t that.
